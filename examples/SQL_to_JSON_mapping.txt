SQL-to-JSON Mapping for the MoMo Database
SQL stores information in tables and rows. JSON stores information as objects and arrays. SQL-to-JSON mapping explains how information from each database table appears in a JSON response.
For this project, the database has these tables:
users
transactions
transaction_categories
transaction_has_categories
System_logs
complete _transaction

The JSON examples use the final state of the supplied SQL data. Therefore, transaction 1 has a fee of 200.00 after the update, and system log 6 is not included because it was deleted.
2. Basic mapping idea
A SQL column usually becomes a JSON property with a similar name.
SQL row:
transaction_id = 2
amount = 8374.00
fee = 0.00

JSON object:
{ "transaction_id": 2, "amount": 8374.00, "fee": 0.00 }

The names are kept similar so that it is easy to understand where each JSON value came from.

All five transaction rows are placed in one JSON array.

Example:

The category name and description are null because the SQL did not include the rows from transaction_categories. The category IDs are known because they appear in the junction-table insert statements.
6. Junction table mapping
The transaction_has_categories table connects transactions to categories.
SQL column
JSON property
Meaning
transaction_id
transaction_id
The transaction being categorized
category_id
category_id
The category assigned to the transaction

Example SQL rows:
(5, 1), (5, 6)

These rows mean that transaction 5 has two categories: category 1 and category 6.
The JSON representation is:
{ "transaction_id": 5, "category_ids": [1, 6] }

Example:

A transaction can have many logs, so logs are represented as an array called system_logs.


8. Complete nested JSON example
This example uses transaction 5 because it demonstrates the many-to-many category relationship.
{
  "transaction_id": 5,
  "amount": 30100.00,
  "fee": 300.00,
  "created_at": "2026-01-07T16:20:00",
  "raw_sms_body": "You have sent 30100 RWF to Butera jean Aime...",
  "sender": {
    "user_id": 5,
    "full_name": null,
    "phone_number": null,
    "user_type": null
  },
  "receiver": {
    "user_id": 2,
    "full_name": "Butera Jean Aime",
    "phone_number": null,
    "user_type": null
  },
  "categories": [
    { "category_id": 1, "category_name": null, "description": null },
    { "category_id": 6, "category_name": null, "description": null }
  ],
  "system_logs": [
    {
      "log_id": 5,
      "user_id": 5,
      "transaction_id": 5,
      "log_level": "WARNING",
      "action_performed": "LOAD",
      "status": "SUCCESS",
      "error_message": "Duplicate category tag ignored"
    }
  ]
}
9. Relationship summary
Database relationship
JSON result
One user sends many transactions
sender_id or nested sender object
One user receives many transactions
receiver_id or nested receiver object 
One transaction has many logs
system_logs array
One transaction has many categories
category_ids array or categories array of objects 
One category belongs to many transactions
The same category can appear in many transactions' arrays
A log without a transaction
A separate system-level log object
